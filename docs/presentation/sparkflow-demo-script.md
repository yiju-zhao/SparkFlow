# SparkFlow 产品汇报演讲逐字稿

**预计时长：8-10 分钟**

---

## 第一章：开场与产品定位（约1.5分钟）

### 1.1 我们要解决什么问题

各位领导好，今天由我来汇报 SparkFlow 这个项目的进展。我们团队在做研究工作的时候发现一个很普遍的痛点——信息太分散了。查会议用一个工具，读论文用一个工具，做笔记又换一个工具，最后做分析还得再开一个。这种来回切换不仅效率低，很多有价值的关联信息也在切换中丢失了。

### 1.2 SparkFlow 是什么

SparkFlow 的定位是一个 **AI 驱动的一站式研究平台**。我们把三件事合在了一起：第一是"探索"，帮你发现会议和论文；第二是"深潜"，让你上传文档跟 AI 深度对话；第三是"生成式交互"，AI 不只是回复文字，它会直接给你渲染出表格和图表。一句话概括就是：**从发现到分析，全程 AI 陪伴**。

### 1.3 当前版本状态

目前产品处于 0.5.0-beta 阶段，前两个核心 Phase 已经全部完成。产品是可以跑起来做完整演示的，接下来我会给大家展示。

---

## 第二章：Demo 演示——探索中心（约2分钟）

### 2.1 会议发现（Conferences）

我们先来看"探索"模块。进入 Explore 页面，这里有四个子功能区。第一个是会议发现，用户可以按会议名称和年份浏览，比如 GTC 2026。所有的会议、场次、论文数据都是结构化存储的，支持快速检索和筛选。

### 2.2 AI 研究助手与生成式 UI

这是我们最核心的差异化能力。用户可以直接用自然语言提问，比如"GTC 2026 有多少个 session"，AI 不是返回一段文字，而是**直接在对话中渲染出一个交互式表格或图表**。这个背后用的是 CopilotKit 的 Generative UI 技术，AI 调用后端工具查数据库，然后把结果以可视化组件的形式呈现出来。这个体验跟传统的纯文本聊天机器人完全不一样。

### 2.3 智能工具箱（Toolbox）

工具箱这块主要解决批量操作的问题。用户可以导入 Excel 数据，然后用 AI 做智能匹配——比如你有一批研究课题，它可以自动帮你匹配到最相关的会议场次或论文。匹配任务支持进度追踪，跑完之后结果直接存在平台里，随时回看。

## 第三章：Demo 演示——深潜笔记本（约2分钟）

### 3.1 多格式文档上传

接下来看 DeepDive 笔记本。每个笔记本就是一个独立的研究空间。用户可以上传 PDF、Word、纯文本文档，也可以直接输入网页链接，系统会通过 Crawl4AI 自动抓取网页内容转成 Markdown 存下来。所有的文档上传之后会自动做分块索引，为后续的 AI 问答做准备。

### 3.2 RAG 智能问答

这是 DeepDive 的核心——基于 RAG 的智能问答。用户可以对已上传的文档提问，AI 会先检索相关的文档片段，然后基于这些片段生成回答。这样做的好处是回答有据可查，不容易"幻觉"。而且我们同时接入了 OpenAI 和 Gemini 两个模型，可以灵活切换。

### 3.3 笔记与对话并行

在做 AI 问答的同时，用户还可以在旁边写 Markdown 笔记。对话历史是持久化保存的，每个笔记本可以有多个对话会话。这样研究过程中的灵感、摘要、分析都不会丢，全在一个地方。

## 第四章：技术架构（约2分钟）

### 4.1 前后端技术选型

技术架构上我们采用的是 Monorepo 结构。前端是 Next.js 16 加 React 19，用 TypeScript 保证类型安全，UI 层用的是 Tailwind CSS 加 Shadcn/UI 组件库，国际化用 next-intl 同时支持中英文。后端 Agent 服务用的是 Python 的 LangGraph 框架做智能体编排，这套方案在可扩展性上非常灵活。

### 4.2 核心基础设施

基础设施这块，数据库用的是 PostgreSQL 17，ORM 是 Prisma 7。文件存储用 MinIO 做 S3 兼容的对象存储。RAG 管线交给 RagFlow 处理文档的分块和检索。网页抓取用 Crawl4AI。整套服务都用 Docker Compose 编排，一键就能拉起来。

### 4.3 AI Agent 架构

Agent 这边目前注册了三个智能体：一个是基于 OpenAI 的 RAG Agent 处理文档问答，一个是基于 Gemini 的 RAG Agent 做备选，还有一个是 Hub Agent 专门负责会议数据查询和生成式 UI 渲染。Agent 通过 LangGraph 的状态图来管理对话流程，工具调用和前端渲染是打通的。

## 第五章：路线图与下一步计划（约1.5分钟）

### 5.1 已完成的里程碑

先快速回顾一下已完成的工作。Phase 1 基础数据层已经全部搞定——核心数据模型、管理后台、会议和论文的数据管理。Phase 2 研究中心也已完成——Explore 界面、AI 助手、生成式 UI 组件，这两个 Phase 构成了产品的基本面。

### 5.2 Phase 3：笔记本集成

接下来最重要的是 Phase 3——**打通探索中心和深潜笔记本**。具体来说，用户在 Explore 里发现了感兴趣的论文或会议，可以一键把这些资料导入到 DeepDive 笔记本里做深度分析。这个"从发现到研究"的闭环一旦打通，产品的核心价值就立住了。我们目前也在探索全局知识库的能力，让不同笔记本之间的知识可以共享和复用。

### 5.3 Phase 4：打磨与上线准备

Phase 4 是整体的打磨阶段，包括 UI/UX 的优化、性能调优、国际化的全面覆盖，以及安全加固和生产环境的部署准备。目标是让产品达到可以给真实用户使用的质量标准。

---

## 第六章：总结（约30秒）

### 6.1 核心价值回顾

总结一下，SparkFlow 的核心价值就是三个词：**发现、深潜、交互**。用探索中心做信息发现，用 AI 笔记本做深度研究，用生成式 UI 让人机交互更直观高效。

### 6.2 团队信心

目前产品的核心功能框架已经成型，技术选型也经过了验证。下一步我们会集中精力把 Phase 3 的笔记本集成做好，这是产品体验形成闭环的关键一步。我们有信心在接下来的迭代中持续交付有价值的功能。
